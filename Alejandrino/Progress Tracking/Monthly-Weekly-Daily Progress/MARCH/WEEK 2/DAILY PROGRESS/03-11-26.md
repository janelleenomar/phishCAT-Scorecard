## 5. Reflection (Qualitative)

**What went well today?**
I successfully bypassed a WAF that was blocking "obvious" SQL injection keywords. By using XML hex entities, I was able to hide my payload from the firewall while still having it executed by the backend database.



**What challenged you?**
Finding the right encoding format was the main hurdle. Standard URL encoding wasn't enough; I had to use the **Hackverter** extension to convert the payload into hex entities that the XML parser would recognize but the WAF would ignore.

**Key learning:**
Firewalls often look for specific strings (like `UNION SELECT`). However, if the application processes data formats like XML, you can encode your input so it looks like gibberish to the firewall but is perfectly readable to the application's internal XML parser.

**Tomorrow's focus:**
Moving into **Blind SQL Injection**, where the application doesn't return results directly in the response, requiring more advanced "conditional" or "time-based" logic.
